## 확인한 동작

- 실제 WASD 입력과 실시간 시뮬레이션 진행. 대각선 속도 정규화와 경계 제한.
- 0, 2, 4초 생성과 총 3마리 제한. 적의 생성 직후 이동, 1초 방향 변경, 경계 정지.
- 플레이어 정지 시 0.65초 공격. 가장 가까운 적 선택. 이동·벽 막힘·상쇄 입력 중 신규 발사 금지.
- 이동 중 기존 투사체 유지, 적의 이동 중 공격, 발사 후 고정 방향, 양쪽 피해와 적 5회 적중 사망.
- 포션 30 회복, HP 상한, 최대 HP에서도 소모, 재획득 금지.
- Pause/Resume 버튼과 Esc. 동결 중 시간·생성·공격·이동·회복·투사체 불변.
- blur/visibilitychange 핸들러와 **실제 Edge 탭 전환**. 입력 해제 및 복귀 시 자동 재개 없음.
- 동시 치명타·포션·마지막 적 사망에서 Game Over 우선.
- 모든 적 처치 전 조기 Stage Clear 방지, 승패 상태 동결.
- 3개 스테이지와 적 공격 주기 1.8 / 1.4 / 1.0초, 최종 단계에서 Next Stage 숨김.
- 모든 상태와 이전 클리어 이력에서 Retry 전체 초기화.
- 1280×900과 390×844 화면에서 배치 확인. 브라우저 JavaScript 오류 0.
- 내장 브라우저에서 직접 키를 눌러 이동·Esc 정지·재개·Retry 확인. 일반 플레이에서 1단계 Stage Clear도 관측.

## 검증 범위의 구분

규칙 검사는 시뮬레이션을 직접 실행합니다. 브라우저의 동시 사망과 3단계 전환 검사는 개발 전용 `?qa=1`의 상태 주입과 수동 시간 진행을 사용했습니다. 일반 모드 실시간 키보드 이동과 정지·재개는 별도 검사했으며, 3단계 전체를 자연 플레이로 완주했다는 의미는 아닙니다.

실제 탭 전환 검사는 합성 이벤트 검사와 별도입니다. Playwright는 기본적으로 모든 페이지에 포커스 모의를 적용하므로 해당 검사에서만 모의를 해제해 네이티브 이벤트를 받았습니다.

## 실행 중 발생한 문제와 처리

1. Sites 설치 도우미가 Windows npm 상대 경로를 프로젝트 내부로 잘못 해석했습니다. 설치된 npm CLI의 실제 경로를 확인해 실행했습니다.
2. 제한된 네트워크에서 npm DNS 조회가 실패했습니다. 네트워크 권한으로 패키지 설치를 완료했습니다.
3. 제한된 프로세스의 로컬 서버를 외부 테스트가 찾지 못해 재실행 포트 충돌이 있었습니다. 소유한 서버를 종료하고 동일한 로컬 주소에서 접속 가능한 권한으로 재시작했습니다.
4. Three.js의 package.json은 패키지 exports에 공개되어 있지 않았습니다. 버전 확인용 진단 명령만 파일 읽기로 변경했습니다.
5. Playwright는 describe 내부에서 headless 옵션을 바꿀 수 없습니다. 실제 포커스 검사를 독립된 `focus.spec.js`로 옮겼습니다.
6. 이 환경의 표시 모드 Chromium 실행이 `spawn UNKNOWN`으로 실패했습니다. Windows에 설치된 Edge의 별도 임시 테스트 프로필로 같은 네이티브 포커스 검사를 수행했습니다.
7. Edge에서도 탭 전환 이벤트가 보이지 않아 확인한 결과 Playwright의 포커스 모의가 원인이었습니다. 테스트에서만 모의를 해제한 뒤 통과했습니다. 게임 코드는 이를 위해 바꾸지 않았습니다.
8. Windows에서 rg에 전달한 경로의 `*.js` 와일드카드가 파일 경로로 해석되었습니다. 디렉터리와 `-g '*.js'` 필터를 분리해 배포 코드 검사를 완료했습니다.
