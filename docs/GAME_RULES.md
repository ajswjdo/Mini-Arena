# MiniArena 규칙과 테스트 방법

## 규칙 값

모든 숫자는 `game/src/rules.js`에 모았습니다. 위치는 `(x, z)`이며 +x는 오른쪽, -z는 위쪽입니다.

| 항목 | 값 |
| --- | --- |
| 아레나 | x, z 각각 -9 ~ 9 |
| 플레이어 시작 | (0, 0), HP 100, 반지름 0.38 |
| 플레이어 이동 | 초당 4, 대각선 정규화 |
| 플레이어 자동 공격 | 0.65초 간격, 피해 20, 투사체 속도 12 |
| 적 | HP 100, 반지름 0.42, 초당 1.2 이동 |
| 적 생성 | 스테이지 0초 (-6, -5), 2초 (6, -5), 4초 (0, 6) |
| 적 방향 | 생성 시 8방향 중 1개, 이후 1초마다 이전과 다른 7방향 중 선택 |
| 적 공격 | 1단계 1.8초 / 2단계 1.4초 / 3단계 1.0초, 피해 10 |
| 적 투사체 | 속도 5, 반지름 0.12, 발사 순간 플레이어 위치를 겨냥 |
| 포션 | (2, 0), 반지름 0.35, 접촉 시 1회 30 회복, 상한 100 |
| 난수 시드 | 12345, Retry 시 초기화 |

속도·크기·위치 중 요구사항에서 수치가 없던 값은 이 첫 구현의 기본값입니다. 플레이어와 적의 중심뿐 아니라 반지름까지 아레나 안에 유지합니다. 적이 벽 쪽 방향을 선택하면 다음 방향 선택 전까지 막힐 수 있습니다. 적과 플레이어의 몸 접촉에는 피해가 없습니다.

## 공격과 충돌

- 플레이어는 첫 공격을 스테이지 시작 0.65초 이후에 합니다. 이후 마지막 발사부터 0.65초를 기다립니다.
- WASD 중 하나라도 눌렸으면 발사하지 않습니다. 벽에 막히거나 A+D처럼 방향이 상쇄돼도 동일합니다.
- 이동 중에도 공격 대기 시간은 흐릅니다. 이미 대기 시간이 지났다면 키를 놓은 다음 틱에 1발 발사합니다. 누적된 발사를 몰아서 처리하지 않습니다.
- 가장 가까운 살아 있는 적을 겨냥합니다. 거리가 같으면 먼저 생성된 적을 선택합니다.
- 적은 생성 시점부터 공격 주기를 계산합니다. 1단계의 두 번째 적 첫 발사는 스테이지 3.8초입니다.
- 적은 움직이면서 공격합니다. 모든 투사체는 발사 뒤 방향이 고정되며 유도되지 않습니다.
- 새로 발사한 투사체는 다음 틱부터 이동합니다. 기존 투사체는 플레이어 이동 여부와 관계없이 계속 움직입니다.
- 투사체는 자기 편에 피해를 주지 않습니다. 첫 대상 적중 또는 아레나 이탈 시 제거합니다.
- 이동 구간과 원형 충돌 범위를 검사해 빠른 투사체가 대상을 건너뛰지 않도록 합니다.

## 같은 타이밍의 판정 순서

시뮬레이션은 초당 120틱입니다. 같은 틱을 같은 타이밍으로 봅니다.

1. 게임 시간 진행, 생성, 플레이어·적 이동, 공격 발사.
2. 기존 투사체 이동과 충돌 계산.
3. 그 틱의 모든 피해를 합산해 플레이어·적 HP에 적용. 적 사망 처리.
4. 플레이어 HP가 0이면 **Game Over**, 포션과 클리어는 처리하지 않음.
5. 살아 있다면 포션 접촉 처리. HP가 100이어도 포션 소모.
6. 3마리가 전부 생성되었고 살아 있는 적이 없으면 **Stage Clear**.

HP는 0 아래로 내려가지 않습니다. Game Over와 Stage Clear에 진입한 이후에는 시간과 시뮬레이션이 멈춥니다.

## 일시정지와 스테이지

- Pause 또는 Esc로 이동·생성·공격·투사체·회복·게임 시간을 전부 동결합니다.
- 창의 `blur`와 문서의 `visibilitychange`를 감지하면 자동 일시정지합니다. 포커스 복귀만으로 재개하지 않습니다.
- 일시정지·승패·Retry·다음 단계 진입 시 입력을 비웁니다. 누르던 키의 반복 keydown은 무시하므로 재개 후에는 키를 놓고 새로 눌러야 합니다.
- Stage Clear 후 Next Stage로 다음 단계에 진입합니다. HP는 유지하고 플레이어 위치·적·포션·투사체·스테이지 시간·발사 대기 시간을 초기화합니다.
- 화면의 GAME TIME은 전체 플레이 시간입니다. 다음 단계에서는 이어지고, 각 단계의 생성·공격 시계 `stageTick`은 0부터 시작합니다.
- 총 3단계이며 마지막 클리어 후 Next Stage는 표시하지 않습니다.
- Retry는 상태와 관계없이 1단계·HP 100·적 1마리·미획득 포션·시간 0·빈 투사체·빈 입력·최초 난수 시드로 되돌립니다.
- 실시간 루프는 매우 긴 프레임의 처리량을 최대 0.1초로 제한합니다. 심한 지연에서는 게임이 느려질 수 있으나 복귀 시 누적 공격을 몰아서 처리하지 않습니다.

## 자동화 인터페이스

표준 테스트 Hook은 일반 화면과 배포 빌드에서도 아래 이름으로 읽을 수 있습니다.

```js
const state = window.__THREE_GAME_TEST_HOOKS__.getState();
// {
//   player: { hp: 100, position: { x: 0, z: 0 } },
//   enemyCount: 1,
//   enemies: [{ id: 1, hp: 100 }],
//   score: 0,
//   stage: 1,
//   gameState: 'playing'
// }
```

- `enemyCount`와 `enemies`는 현재 살아 있는 적만 포함합니다. 적 HP는 `id`로 구분합니다.
- `score`는 별도 점수 체계를 추가하지 않고 **현재 스테이지의 적 처치 수**(`defeated`)를 그대로 읽습니다. 다음 단계와 Retry에서 0으로 초기화됩니다.
- `gameState`: `playing`, `paused`, `game-over`, `stage-clear`.
- `getState()`는 실제 시뮬레이션 스냅샷에서 복사본을 만듭니다. 조회는 시간·전투·난수 상태를 바꾸지 않으며, 반환값을 수정해도 게임에는 반영되지 않습니다.
- 개발 서버의 `?qa=1`에서만 `window.__THREE_GAME_TEST_HOOKS__.reset()`도 제공합니다. UI Retry와 동일한 `simulation.retry()`를 호출하고 화면과 프레임 누적 시간을 갱신합니다. HP·점수·승패를 별도로 계산하거나 강제 설정하지 않습니다.
- 일반 화면과 배포 빌드에는 `getState()`만 있으며, 기존 `__ARENA__`와 개발 전용 `__ARENA_QA__`는 계속 사용할 수 있습니다.

일반 화면에는 읽기 전용 스냅샷만 제공합니다. 스냅샷은 복사본이라 수정해도 게임에 반영되지 않습니다.

```js
window.__ARENA__.snapshot()
// status, stage, tick, stageTick, time, stageTime,
// player, enemies, projectiles, potion, input, rng, spawned, defeated ...
```

개발 서버의 `http://127.0.0.1:5173/?qa=1`에서는 자동 시간 진행을 멈추고 아래 도구를 제공합니다. 배포 빌드에서는 활성화되지 않습니다.

```js
window.__ARENA_QA__.snapshot();
window.__ARENA_QA__.advance(0.65); // 정확히 78틱 진행. Pause/승패이면 진행하지 않음.
window.__ARENA_QA__.retry();
window.__ARENA_QA__.load(snapshot); // 동시 사망 등 특정 상황을 위한 테스트 데이터 주입
```

QA 모드에서도 실제 키보드·버튼 이벤트와 화면 렌더링은 그대로 동작합니다. `advance` 시간은 가장 가까운 1/120초 단위로 반올림합니다. `load`는 개발용이므로 유효한 스냅샷을 전달해야 합니다.

UI에는 `data-testid`를 붙였습니다: `hp`, `stage`, `time`, `status`, `defeated`, `pause`, `resume`, `retry`, `overlay-retry`, `next-stage`, `potion-status`, `enemy-interval`.

Playwright는 기본적으로 모든 탭에 포커스 모의를 켜므로 실제 탭 전환 검사에서는 CDP의 `Emulation.setFocusEmulationEnabled`를 false로 설정합니다. 이는 테스트 환경 설정이며 게임 코드의 우회가 아닙니다.
